# Rachel Studio AI Tool Orchestration

Date: 2026-05-03

Purpose: define how Rachel Studio uses multiple AI tools together to build luxury real estate launches at the standard.

## The Point

Rachel Studio should let Rachel bring the right AI tool to the right part of the job.

No single tool has to be everything.

The platform coordinates them.

## What Each Tool Should Not Do

Rocky should not have to be the deployment engineer for everything.

Codex should not invent taste without Rachel/Rocky.

Claude should not publish source claims without a safety register.

NotebookLM should not be treated as the final approval record or builder.

The writing LLM should not invent facts, override locked copy, or bypass Rachel/Rocky approval.

Visual AI should not create final property images unless Rachel approves and the asset is marked clearly.

Cloudinary should not be a junk drawer.

Remotion should not replace the locked hero video unless Rachel explicitly changes the lock.

Video AI should not invent property facts, publish directly, or replace original footage.

SEO should not be an afterthought.

- Rocky
- NotebookLM
- Claude

- human-readable Workspace record

## The Platform Promise

Rachel should be able to say:

`Make this property launch feel like Vogue / Met / Real Estate, but make sure every claim, image, source, SEO tag, crop, and video asset is controlled.`

And Rachel Studio should route the work:

- Rocky protects taste and memory
- NotebookLM helps Rachel interrogate sources and mockup directions
- Claude protects source reasoning
- Codex protects execution
- Cloudinary protects media truth
- Remotion protects video output
- SEO backend protects discoverability
- Google Workspace protects shared memory, approvals, and source records
- Rachel approves the final work
